# 视频证据协议

版本：`0.1`

## 目标

本协议用于回答“视频实际说了什么、展示了什么，以及我们能够据此得出什么结论”。它优先保证可追溯性，而不是笔记生成速度。

## 三层证据

### E0：机器采集层

包括：

- 平台返回的元数据；
- UP 主提供或平台公开的字幕；
- 下载的音视频文件；
- ASR 自动转写；
- 自动提取的关键帧；
- 工具版本、命令、时间和文件哈希。

E0 只证明“机器取得了这些材料”，不证明自动转写准确，也不证明材料中的观点正确。

### E1：人工核对层

核对者必须：

- 按时间轴回听全部语音；
- 对专名、数字、否定词和逻辑连接词重点复核；
- 同时查看画面中的标题、字幕、图表和引用；
- 无法确认时保留 `[听不清]`、`[画面不清]`，不得补写；
- 记录所有实质性修改。

只有 E1 文本可以称为“经核对的逐字稿”。

### E2：解释层

每项解释必须标记类型：

| 类型 | 含义 | 最低证据要求 |
| --- | --- | --- |
| `QUOTE` | 经 E1 核对的短原话 | 时间戳＋逐字稿段号 |
| `PARAPHRASE` | 对明确原意的转述 | 时间范围＋相关段号 |
| `VISUAL` | 仅由画面提供的信息 | 时间戳＋关键帧编号 |
| `INFERENCE` | 分析者推导出的含义 | 至少一项直接证据＋推导过程 |
| `UNRESOLVED` | 证据不足或存在多解 | 列出缺失证据，不给确定结论 |

## 完整解读最低要求

一份“完整解读”至少包括：

1. 视频基本信息与证据包哈希；
2. 按自然段落划分的时间轴；
3. 每段的明确主张、例子、论证连接和结论；
4. 画面提供但音轨未说出的信息；
5. 视频明确使用的事实、评价和假设；
6. 作者没有说什么，避免把分析者观点归给作者；
7. 疑难片段和未解决问题；
8. 若用于其他项目，单列“可借方法”，不得混入视频复述。

## 禁止事项

- 依据标题、简介或评论补全视频论证；
- 用模型常识修正说话者的实际表述；
- 把自动标点、同音字识别或专名猜测当作原话；
- 把弹幕、评论区和视频作者观点混在一起；
- 把视频中的二手事实未经核验写成现实事实；
- 为了让论证更漂亮而省略反例、限定词或自我保留。

## 建议工作顺序

```text
doctor
  ↓
collect（保留 E0）
  ↓
人工回听并生成 E1
  ↓
关键帧逐段复核
  ↓
填写 evidence-map.md
  ↓
verify（确认 E0 未被改动）
```
